먼저 봐주실 것

요청은 두 덩어리입니다. 1~4번(화면 이동·메뉴)은 대부분 “화면마다 고유한 주소(URL)를 갖게 한다” 하나로 함께 풀립니다. 5~7번은 현장 워크숍에서 새로 확인된 것으로, “무엇을 해야 하는지, 제대로 했는지 알려달라”는 요구입니다. 현장에서 나온 “입력 작업은 전화로 물어보는 게 빠르다”는 말이 5~7번을 요청하는 이유입니다.

요청 사항

01

메뉴 링크를 실제 주소로

필수
지금

화면마다 주소는 이미 있습니다(/pre_rec_mgmt/P0070/P0070_main.do?menuId=M016P0001). 그런데 좌측 메뉴 링크가 href="javaScript:subMenu_on(...)" 형태여서, Ctrl+클릭·가운데 클릭·우클릭 “새 탭에서 열기”가 전부 동작하지 않습니다. 현장 발언 “화면이 옆으로 열리지 않는다”가 여기서 나옵니다.

요청

메뉴 <a>의 href에 실제 주소를 넣어 주세요. 이동 동작은 지금처럼 스크립트로 처리하되(onclick에서 preventDefault), href만 진짜 주소면 브라우저 기본 기능이 그대로 살아납니다.

확인 방법
  • 「재고현황」을 Ctrl+클릭하면 새 탭에서 재고현황이 열린다
  • 메뉴에 우클릭 → “새 탭에서 열기” 항목이 나타난다
  • 메뉴에 마우스를 올리면 브라우저 하단에 주소가 표시된다

가장 적은 공수로 가장 큰 효과가 나는 항목입니다. 화면을 새로 만들 필요 없이 링크 속성만 바꾸면 새 탭·즐겨찾기·링크 공유가 한꺼번에 열립니다.

02

화면 안에 뒤로가기와 현재 위치

권장
지금

브라우저 뒤로가기는 동작합니다. 다만 화면 안에 뒤로가기 버튼도, 현재 위치 표시도 없어 사용자는 홈으로 나갔다가 메뉴를 처음부터 다시 찾습니다. 지금 어느 메뉴 안에 있는지도 화면에 적혀 있지 않습니다.

요청

화면 상단에 ← 뒤로 버튼과 현재 위치(기록일지 › 일일일지)를 넣어 주세요. 경로의 상위를 누르면 그 그룹으로 이동합니다.

확인 방법
  • 일일일지 화면 상단에 “기록일지 › 일일일지”가 보인다
  • ← 버튼을 누르면 직전 화면으로 돌아온다
02-B

일일·주간·월간·연간 일지를 한 화면으로

필수
지금

「기록일지 관리」 안에 일일일지 · 주간일지 · 월간일지 · 연간일지가 각각 별도 메뉴로 있습니다. 주기는 시스템이 아는 정보인데 사용자가 대신 판단하고 있습니다. 실무자는 “오늘 뭘 써야 하지”로 생각하지 “주간 메뉴로 가야지”로 생각하지 않습니다. 여기에 검교정일정·유효성평가·자가품질검사·보건증·입고성적서까지 같은 곳에 섞여 12개가 나열돼 있습니다.

요청
  • 「선행요건 양식 설정」에 주기·기한·근거 항목을 추가해 주세요 — 이것이 전제입니다. 지금은 항목만 정할 수 있고 주기를 정할 수 없어, 주기가 메뉴에 박혀 있습니다. (주기: 일 / 주+요일 / 월+일자 / 분기 / 반기 / 연 / 수시 / 이벤트)
  • 네 메뉴를 「일지 작성」 하나로 합치고, 주기는 화면 안 필터로 — 필터 이름은 쓰시던 그대로(일일일지·주간일지·월간일지·연간일지) 유지
  • 기본값은 “오늘 써야 할 것” — 주기 계산은 시스템이 수행
  • 각 행에 미작성 / 작성완료 / 결재대기 상태 표시
  • 일지가 아닌 검교정·유효성평가·자가품질검사·보건증은 기한 관리 성격이므로 07번(법정 일정)으로 이동
확인 방법
  • 월요일에 들어가면 주간일지가 “오늘 써야 할 것”에 함께 나온다
  • 월초에 들어가면 월간일지가 함께 나온다
  • 필터를 “월간”으로 바꾸면 월간 대상만 남는다

동작하는 화면은 시안 v2의 「기록일지 › 일지 작성」에서 눌러보실 수 있습니다.

03

좌측 메뉴 정리

권장
지금

1단계 11개와 2단계 10개가 한꺼번에 펼쳐져 화면 밖으로 넘어갑니다. 2단계는 앞에 붙은 - 하나로만 구분돼 상하위 관계가 잘 보이지 않습니다.

요청
  • 평소에는 1단계만 보이고, 누른 그룹 하나만 펼쳐지게
  • 메뉴 위쪽에 검색창 추가 (두 글자만 입력해도 걸러지도록)
  • 2단계는 들여쓰기와 세로선으로 단계가 보이게
  • 메뉴를 접어 아이콘만 남기는 버튼 추가
확인 방법
  • 노트북 화면(1366×768)에서 스크롤 없이 1단계 메뉴가 전부 보인다
  • 검색창에 “재고”를 입력하면 재고 관련 메뉴만 남는다

화면단만 수정하면 되는 항목이라 가장 먼저, 가장 적은 공수로 반영 가능할 것으로 봅니다.

04

여러 화면 동시에 열기

협의
지금

입고등록을 입력하다가 재고현황을 확인하러 가면, 입력하던 내용이 사라집니다.

요청

화면 상단에 탭을 두어 여러 화면을 동시에 열어두고, 탭을 오가도 입력값이 유지되게 해 주세요. (탭 최대 8개, 닫기·고정 가능)

확인 방법
  • 입고등록에 3건을 입력한 뒤 재고현황 탭으로 갔다가 돌아오면 입력값이 그대로 남아 있다

공수가 크다면 대안으로 — 1번(고유 주소)만 반영되면, 메뉴를 Ctrl+클릭 또는 우클릭으로 새 브라우저 탭에서 열기가 가능해집니다. 이것만으로도 실무 불편은 상당 부분 해소되니, 이 방식으로 먼저 검토해 주셔도 좋습니다.

05

해야 할 일지와 누락 알림

필수
지금

오늘 어떤 일지를 써야 하는지 시스템이 알려주지 않습니다. 현장 발언 — “해야 할 일지 목록을 모른다”, “일지 누락에 대한 확인을 모른다”.

요청

로그인 직후 첫 화면에 오늘 써야 할 일지와 기한이 지난 미작성 건을 목록으로 보여주고, 누르면 해당 입력 화면으로 바로 이동하게 해 주세요. 좌측 메뉴에도 미처리 건수를 숫자로 표시해 주세요.

확인 방법
  • 어제 일지를 일부러 비워두면, 오늘 첫 화면에 그 건이 표시된다
  • 그 줄을 누르면 해당 일지 입력 화면이 바로 열린다
  • 작성을 마치면 목록과 메뉴 배지에서 사라진다

현장 요구 중 가장 반복해서 나온 항목입니다. 메뉴 개선보다 체감이 큽니다.

06

작성 내용 검증

필수
지금

저장은 되지만 맞게 썼는지 알려주지 않아, 결국 전화로 확인합니다. 현장 발언 — “일지 작성 시 맞는지 틀린지 모른다”, “데이터의 정확도가 눈에 보이지 않는다”, “입력 작업은 전화로 물어보는 게 빠르다”.

요청

저장할 때 한계기준 위반·필수 빈칸·앞뒤 기록 불일치를 그 자리에서 표시해 주세요. 막는 것이 아니라 “이 값은 기준을 벗어났습니다”처럼 알려주는 방식이면 됩니다.

확인 방법
  • 가열 온도를 한계기준 미만으로 입력하면 저장 시 경고가 표시된다
  • 필수 항목을 비우고 저장하면 어느 칸인지 화면에서 짚어준다
  • 사용량이 재고보다 많으면 그 자리에서 알려준다
07

법정 일정 안내

권장
지금

기한이 있는 의무를 시스템이 챙겨주지 않아 담당자가 기억에 의존합니다. 현장 발언 — “정기·수시점검 대상 안내를 모른다”, “생산실적 보고서 제출 방법·기간을 모른다”, “검교정 하는 법을 모른다”, “3년 해썹 재갱신을 못 했다”.

요청

정기·수시점검 / 검교정 / 교육훈련 / 생산실적 보고 / 인증 갱신의 다음 기한을 한 화면에 모으고, 기한이 다가오면 첫 화면에 표시해 주세요.

확인 방법
  • 인증 만료일을 등록하면 남은 기간이 첫 화면에 표시된다
  • 검교정 주기를 넘긴 설비가 목록에 뜬다

회수(리콜) 관리와 수출서류는 현재 시스템에 없는 기능입니다. 성격이 다르므로 이 요청서와 분리해 별도 협의를 요청드립니다.

진행 순서 제안

1차

05 · 06 — 일지 누락 알림과 작성 검증

현장 체감이 가장 큰 항목입니다. “전화로 물어보는 게 빠르다”는 상황을 없애는 것이 이번 개선의 목표입니다.

1차

01 · 02 · 03 — 주소 부여, 뒤로가기, 메뉴 정리

매일 겪는 불편이고 화면단 작업 비중이 커서, 같은 단계에 함께 반영을 요청드립니다.

2차

07 — 법정 일정 안내

기한 데이터를 어디서 받을지(업체 입력 / 인증원 연계) 먼저 정해야 하므로 다음 단계로 둡니다.

2차

04 — 동시 탭

공수와 일정 확인 후 별도 협의합니다. 위의 새 브라우저 탭 방식으로 대체 가능한지 함께 검토 부탁드립니다.

별건

회수관리 · 수출서류 · 서식 직접 수정

현재 시스템에 없거나 범위가 큰 기능입니다. 이 요청서와 분리해 별도 견적·일정으로 협의를 요청드립니다.

회신 부탁드릴 내용

  1. 항목별 반영 가능 여부와, 어려운 항목은 그 사유
  2. 항목별 예상 소요 기간과 반영 일정
  3. 무상 개선 / 별도 비용 구분과 그 근거
  4. 현재 화면 전환이 어떤 방식(프레임 · 새로고침 · 단일 페이지)인지와, 주소 부여 시 영향 받는 범위

참고 시안은 동작 이해를 돕기 위한 예시이며, 화면 디자인이나 구현 방식을 지정하는 것은 아닙니다. 시안 속 데이터는 임의로 넣은 예시이고, 2단계 메뉴는 「원료수불/생산일지」만 실제 항목입니다.
